# Impeccable — SignalPlayback

## Design Context

### Users

Three overlapping people, one binary:

- **RF / radar engineers at a lab bench.** Long sessions, dim room, a scope
  already on the desk. They think in PRF, pulse width, coding, SNR. They came
  to look at samples, not at software.
- **DSP developers in a dev loop.** Editor and terminal open beside the app.
  Write a stage → run → diff → repeat. The app is one window in a toolchain
  and must not act like the main event.
- **Analysts / test engineers.** Less authoring, more inspecting: verify a
  dataset, read a run, promote a baseline, pull a number into a report.

Job to be done: *get from a pile of signals to a trustworthy answer about an
algorithm, and be able to show your work.* Every screen is either evidence or
a control over evidence.

Emotional target: **confidence and calm**. The user should trust that the
number on screen is the number in the database. No delight that costs a
millisecond of doubt.

### Brand Personality

Three words: **precise, mechanical, unimpressed.**

Voice: states facts, gives units, never congratulates. "4 groups · 2.1 s" not
"Great! Your run finished successfully." Errors name what was wrong and where.
Empty states teach the next action in one line.

### Aesthetic Direction

**Refined studio tool.** The DAW / NLE / bench-instrument lineage: quiet
chrome that recedes, precise controls, and colour spent almost entirely on
signal and state. The window frame is grey; the data is not.

Theme: **dark by default, light a first-class alternative** (long dim-room
sessions; light exists for projectors, screenshots and printed reports).
Both are designed, neither is an afterthought.

Anti-references — this must never read as:

- a generic SaaS dashboard (cards in cards, rounded rects, drop shadows,
  metric tiles, purple/blue gradients),
- consumer or toy software (mascots, bouncy easing, oversized friendly copy),
- untouched Iced/Qt defaults — the current state; it must read as deliberately
  designed,
- cyberpunk signal kitsch (neon cyan on black, glow, scanlines, matrix green).

#### Typography

The app embeds its faces (`crates/sp-app/assets/fonts/`) and loads them in
`main.rs`, so it renders identically on every machine rather than falling back
to the platform default.

- **UI / display: Archivo** (variable, OFL). An engineered grotesque with a
  width axis. Use the *width* axis for hierarchy the way an instrument panel
  does: screen titles and section labels set wider and tighter-tracked, body
  UI at normal width. One family, two behaviours.
- **Numerals, tables, code, readouts: Martian Mono Condensed** (OFL). Narrow
  enough that a sample table fits more columns, tabular figures for value
  columns, and it carries the CSV/expression/assertion text without a second
  personality. (Iosevka was the first choice and is not distributed as static
  TTFs that can be fetched and embedded, so this is the substitute; the brief
  it satisfies is unchanged.)
- Never mono as decoration. Mono means *this is a literal value*.
- Tabular figures everywhere a number can change in place (transport clock,
  statistics, run timings). Digits must not reflow.
- Type scale: 5 fixed `rem`-equivalent steps, ratio ≥ 1.25. This is a product
  UI — fixed steps, no fluid `clamp()`.

#### Colour

Brand hue is a warm amber-ochre (oklch h ≈ 70), not phosphor amber. Work in
OKLCH.

- **Neutrals are tinted toward the brand hue** at chroma ≈ 0.006 — warm
  graphite, never a blue-grey and never pure `#000`/`#fff`.
- **Accent** `oklch(0.72 0.15 68)` — selection, focus, the playhead, the
  active stage. Rare by construction: roughly 10% of visual weight.
- **State**: pass `oklch(0.70 0.11 150)`, fail `oklch(0.62 0.17 25)`, warn on
  the brand ochre. Reduce chroma as lightness approaches the extremes.
- **Traces keep the Okabe–Ito palette** already specified in `DESIGN.md`
  §"Accessibility", and identity is *also* carried by legend and line style —
  never colour alone.
- Chrome colour and data colour come from different budgets. If a UI surface
  competes with a trace, the surface is wrong.

### Design Principles

1. **The data is the interface.** Chrome recedes; samples, traces and numbers
   are the only things allowed to be loud. Any pixel that isn't evidence or a
   control over evidence should justify itself or go.
2. **Density is a feature.** These users want more rows on screen, not more
   whitespace. Rhythm comes from varied spacing on a 4pt scale and from rules
   and alignment — not from padding everything equally or wrapping it in a
   card. Not everything needs a container; nothing needs two.
3. **Instrument, not app.** Borrow from bench hardware and studio tools:
   silkscreen-style labels, hard alignment, monospaced readouts, controls that
   look like they have a defined range. Zero decorative flourish.
4. **Colour is a signal.** Every use of colour must mean something — state,
   selection, or trace identity. A colour that means nothing is a bug.
5. **Motion only for state.** Transport, playhead, stage transitions,
   entrances and exits. Transform and opacity only, exponential ease-out, and
   nothing that delays a user who already knows where they're going. No bounce.
